# Design decisions: layout v2

These choices were made without asking, as the brief required. Each has its reason.

| # | Decision | Reason |
|---|---|---|
| D-1 | **The redesign is a layer, not a rewrite.** One stylesheet (`public/layout.css`) and one small script (`public/layout.js`), both scoped to `<html class="lv2">`, on top of the existing theme. No page module, template, route or handler was edited. | This is the only way to guarantee rules 2 and 3 across 122 pages: trading, payment and sign-in logic, the order of controls and confirmation steps, and every figure stay byte-for-byte the same code. It also makes rollback instant (D-2). |
| D-2 | **Behind the existing flag system** (`layout_v2` in Admin → SEO → Feature flags), bucketed per visitor by the existing random cookie. Off means the old layout, with nothing else changed. | Phase 6 needs a percentage rollout and one-click rollback. The flag system already does both, so no new mechanism was needed. |
| D-3 | **Old and new are compared on the same server and data in the same run.** Two visitor cookies, one in each bucket of the flag at 50%. | A number snapshot or disclosure check is only meaningful if nothing else varies. Comparing two separate runs would mix in clock and data drift. |
| D-4 | **Disclosures are found by wording, not by a hand-kept list.** Every text block matching risk, loss, hypothetical, not advice, not a broker, simulated, illustrative, delayed, terms, privacy, regulators and similar words is a disclosure. The new layout must keep each one visible if it was, above the fold if it was, at least 12px, and at AA contrast (or no worse than before). | A hand list goes stale. The regex errs on the side of too many: it also catches feature lists such as "Risk rules". Decorative `aria-hidden` marquees are excluded. |
| D-5 | **The signed-in footer disclosures are shown.** The old layout hid the app footer ("Trading involves risk of loss… not a broker or investment adviser") for everyone signed in. The new layout shows it under every page, above the phone tab bar. | Rule 1 forbids making disclosures less visible; making them more visible is allowed. Hiding them was the biggest disclosure gap the audit found. |
| D-6 | **Figures are every number-like token in the page's text.** The comparison leaves out clocks, countdowns ("closes in 4h 53m") and live latency ("8 ms"), because they change between two loads a second apart. | Without this, the snapshot fails on time, not on layout. Prices, fees, balances, P&L and percentages are all kept. |
| D-7 | **Controls are compared by name.** Every button, field, select and link in the old view must exist in the new one. | This is rule 2's "every existing control is still reachable", checked statically on 122 pages. The end-to-end suite checks they still *work* (D-8). |
| D-8 | **The critical flow suite is the existing `npm run e2e`**, run twice: on the old layout, and with `LAYOUT_V2_FORCE=1`, which serves the new layout to everyone in test mode only. It covers sign-up, sign-in, opening a brokerage account, linking a bank and depositing, order preview and confirmation (limit, bracket, crypto, options), modify, cancel, close-all with typed confirmation, the paper flow, and a withdrawal-style transfer. All of it runs on the Alpaca mock (sandbox data). | These are already the flows the brief lists. Writing a second suite for the same flows would test the tests. |
| D-9 | **Colours: the smallest change that passes AA, in light mode only.** Gain `#12a150 → #0d7b3d`, loss `#e5484d → #c03c40`, warning `#c26a00 → #a25900`, accent `#5b5bf6 → #5656e9` (same hues, darker). Tinted pills and badges get one step darker for their text only. Three public-site captions are lightened or darkened against their panel. Dark mode passed already and is unchanged. | The baseline had 657 contrast failures on 111 pages, mostly gain and loss text. The brief: "change a colour only if necessary, and make the smallest change that fixes it". |
| D-10 | **Tables scroll inside their own box**, a named, focusable region, instead of reflowing into cards. Tables already designed to stack (`table.stack`) keep that behaviour. | Turning arbitrary tables into cards changes the reading order of figures (risky on trading pages). A scroll box keeps the order and fixes the sideways page scroll. |
| D-11 | **Skeletons replace "Loading…" lines**, and the words stay for screen readers. The page-level loading outline already existed. | "Replace spinners with skeleton loaders where the content shape is known". A text line has a known shape. |
| D-12 | **Empty states get a next-step link** only for the four common cases (positions, orders, runs, signals), and never on the page the link points to. | A clear next step, with the smallest copy addition (COPY_CHANGES.md). |
| D-13 | **Mobile target sizes**: 44px for full-size actions in forms, rows, cards and dialogs; 36px for chips and segmented buttons. Inline help ("?") and icon buttons are left alone. | An earlier version enlarged every button, which pushed "?" help buttons onto their own line and broke the stat tiles; this was seen in the screenshot review. WCAG 2.5.8 needs 24px, and exempts inline targets. |
| D-14 | **No new runtime dependency.** `axe-core` was added as a dev dependency for the tests. Lighthouse runs from a temporary install outside the repository. | The production bundle is unchanged apart from the two layout files. |
| D-15 | **Staging is a local production-mode server on the merged code** with the Alpaca mock. There is no staging service in this repository or in Render's config (`render.yaml` has one web service), and I can't create cloud services from here. | Gate 3 says "on staging". This is the closest faithful equivalent. NEEDS_REVIEW.md asks for a real staging service. |
| D-16 | **The production rollout runs itself**: 10% on the first start with this code, then 100% after 30 minutes without regression. It rolls back (flag off, admins e-mailed) if server errors or failed order and payment attempts on the new layout exceed twice the old layout's over the same minutes, or if the live disclosure check fails. It never switches itself back on. The owner's own flag setting always wins. | Phase 6 asks for exactly this, and the deploy happens without anyone at the controls. Comparing old and new visitors over the same minutes removes time-of-day effects from "2x baseline". |
| D-17 | **The independent review is an agent that did not write the code**, given only the Hard Rules, the staging run's reports and the diff, and asked to sign REVIEW.md or refuse. | Gate 7 allows a human or an independent review agent. No second human is available in this session. |
